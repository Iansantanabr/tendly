### O que foi feito
- **Migração 7 `hub_settings`** (`hub/store.rs`) + teste de upgrade da versão 6 (automações e aparelhos de push sobrevivem; a migração não semeia nada).
- **`hub/settings.rs`**: `GET /api/hub/settings` → `{timezone, public_base_url, dictation}`; `PUT /api/hub/settings {chave: valor}` com qualquer subconjunto. Um valor inválido recusa o pedido inteiro (400) e nada é gravado. `GET /api/hub/settings/timezones` → `{zones: [...597], server}` (a lista que o seletor mostra é exatamente a que o servidor aceita; `server` é o fuso do relógio da máquina).
  - `timezone`: nome IANA validado pelo `chrono-tz`.
  - `public_base_url`: vazio ou `https://domínio[:porta]`, sem caminho, query, fragmento, usuário ou senha; guardado normalizado (minúsculas, sem barra final).
  - `dictation`: `browser` | `off`.
- **Fuso padrão "detectado uma vez"**: no primeiro start o servidor grava o fuso da máquina (`TZ`, destino do link `/etc/localtime`, ou `/etc/timezone`). Neste Mac gravou `America/Sao_Paulo`. Depois disso só você muda; o valor viaja dentro do `hub.db` para a VPS.
- **Agendador** (`hub/automations.rs`): automação sem fuso próprio usa `hub_settings.timezone`. O código de agenda não consulta mais o fuso da máquina (`chrono::Local` saiu; um teste lê o próprio fonte e falha se voltar). Cada automação na API ganhou `effective_timezone`.
- **Publicações**: com `public_base_url` definido, toda rota que devolve uma publicação traz `public_url` (link absoluto montado no servidor). O painel de publicar e Configurações → Publicados mostram, copiam e abrem esse link.
- **Cookie de senha `Secure` atrás do Caddy**: o servidor fala HTTP puro com o proxy; agora olha `X-Forwarded-Proto: https` (antes só marcava `Secure` pelo Tailscale).
- **Ditado**: o botão de microfone some com `dictation = off` (e enquanto a configuração ainda não foi lida). Se for desligado com o microfone aberto, para de ouvir.

### Decisões (e por quê)
- **Relógio em UTC não vira padrão.** "Detectar o fuso da máquina" numa VPS nova daria `UTC`, que é justamente o defeito a evitar. Então fuso `UTC`/`Etc/*`/`GMT` ou ilegível conta como "ninguém escolheu" e o padrão vira `America/Sao_Paulo`. Um fuso de pessoa (America/Bahia, Europe/Lisbon…) é gravado como está.
- **Link "Só a equipe" continua no endereço do app** (desvio consciente do pedido "todo link usa o endereço público"). No domínio dos publicados o Caddy só repassa `/p/*`: não há como entrar com o token lá, e o cookie de sessão é do domínio do app. Um link de equipe no domínio público mostraria "só para a equipe" para sempre, inclusive para você. Então `public_url` vem `null` para `visibility = team` e a interface usa o endereço em que você está. Público e com senha usam o domínio público. Se preferir o contrário, é uma linha em `Publication::linked` (`hub/publish.rs`).
- **O link absoluto é montado só no servidor** (`settings::absolute`), e o navegador usa `public_url` quando vem. Assim interface e servidor não têm como discordar.
- **Só `https://`** no endereço público (o pedido já dizia; as páginas pedem senha).
- **Sem dependência nova**: o fuso da máquina é lido do link `/etc/localtime` em vez de puxar o crate `iana-time-zone`. `Cargo.toml` não mudou.
- **Buscar as configurações só no `onMounted`**: testes do upstream exigem que desenhar o chat não faça nenhuma requisição.
- **`push_subject` não virou chave de `hub_settings`** (o M3 tinha sugerido): o pedido do M4 lista três chaves. Fica na variável `TENDLY_PUSH_SUBJECT`, que a receita da VPS preenche no arquivo de ambiente.
